## High, triaged
1. `reentrancy-balance` CrossCurrencySettler._swap: balance delta measured around a router call. **False positive / by design**: the measured delta is the point (comment says "measured, not trusted"), and a short fill reverts via `MinOutNotMet`. Entry point is `nonReentrant`.
2. `reentrancy-balance` CrossCurrencySettler._pull: same pattern around `receiveWithAuthorization`; mismatch reverts `PullMismatch`. **False positive.**

## Medium, triaged
- `incorrect-equality` (10): `eta == 0`, `bal == 0`, enum equality. These are existence/zero checks on timelock ETAs and enums, not balance-manipulable equality. **False positives.**
- `unused-return` (8): ignored tuple/return values (`paymentState` held amount, `reimburse`, router output). Router output is deliberately re-measured by balance; `reimburse` return not needed. **Benign.** Optional: check `flushToVault()` return in EscrowDepositRouteFactory._credit.
- `uninitialized-local` (7): Solidity zero-initializes locals; intentional. **False positives.**
- `divide-before-multiply` JobEscrow._distribute: `gross*evaluatorFeeBps/BPS` after `amount*payoutBps/BPS`: rounding dust of at most 1 wei-unit of USDC (6 decimals), and the remainder goes to the provider/client so nothing is lost. **Accepted rounding.**
- `reentrancy-no-eth` arbiter `rule()` (v0.1 and V03): external calls to REGISTRY/TOKEN/ESCROW before final state; **mitigated**: `rule` is `nonReentrant`, state set to Finalized before any external call (code comment), caller must be the arbitrator. False positive.
- `reentrancy-no-eth` UMAArbitratorAdapter.proposeRuling: writes `pendingAssertion` after `oracle.assertTruth`. **Low real risk** (oracle is trusted UMA OOv3, callbacks gated by `msg.sender == oracle`; contract is not deployed). **Hardening suggestion (the only one worth doing):** add `nonReentrant` or write `pendingAssertion` before the call (set then revert-on-failure).

## Low / Info
- 62 `timestamp`: deadlines and timelocks legitimately use block.timestamp.
- 7 `missing-zero-check`: constructor/setter address params without zero-address checks. Hardening only.
- Others: naming, unindexed address event params, assembly (OZ-style), low-level calls.

## High/Medium findings Developer should fix
**None are exploitable.** Optional hardening, all low priority and testnet-irrelevant until a mainnet candidate:
1. UMAArbitratorAdapter.proposeRuling: `nonReentrant` / CEI ordering.
2. Add zero-address checks to the 7 flagged setters/constructors.
3. Add `// slither-disable-next-line` annotations with justifications for the confirmed false positives, and a `slither.config.json` (filter lib/test/script/mocks) so scans are reproducible in CI.

## Limits
Static analysis only: no fuzzing run, no economic/game-theory review of the evaluator slashing model, no review of off-chain components (router, judge service, relayer). A professional audit remains required before any mainnet use.
